# 0.84 测试操作说明

安装包：`MGControl-V0.84-widget-ready-unsigned.ipa`（带小组件）、`MGControl-V0.84-app-only-ready-unsigned.ipa`（纯 App）、`MGControl-V0.84-widget-trollstore-appgroups.ipa`（TrollStore 专用）。三包都未签名，需自行重签或 TrollStore 安装。已有钥匙和账号保留，覆盖升级即可，**不要清除或重新领取钥匙**。

## 一、14101 修复（本次重点）

现象回顾：车况刷新、车辆列表都是 200，只有蓝牙钥匙页报「服务端拒绝本次检查，代码：14101」。原因是车控走的是最新一次登录的 MP 直连凭据，数字钥匙走的是早先交换保存的车辆平台凭据；后者被服务端作废时，车控看不出来，只有钥匙报错。所以在官方 App 里删钥匙、重领、忽略蓝牙都无效。

1. **覆盖安装 0.84，不要退出登录、不要删钥匙。**
2. 打开「蓝牙钥匙」页，点「检查授权」。
3. 预期：不再直接报 14101。诊断里会出现一行「数字钥匙：车辆平台凭据被判定失效（业务码 14101）；用最新登录重新交换后重试一次」，随后检查通过。
   - 如果通过：继续做一次蓝牙连接，确认能正常认证、能锁车/解锁。说明旧凭据已自愈，不需要重登。
   - 如果仍报错：新文案会给出三步核对顺序（官方 App 钥匙状态、是否车主账号、重新登录主账号）。此时按顺序做，并把诊断里的「交换凭据已更新/未变化」这一行记下来。
4. **判读方法**：
   - 「交换凭据已更新」+ 仍然 14101 → 服务端换了新凭据还是不认，几乎可以确定是账号/车辆没有数字钥匙权限，不是本机凭据问题。
   - 「交换凭据未变化」+ 仍然 14101 → 服务端认为这份凭据仍然有效却拒绝该接口，需要抓包对比官方 App 同一接口的令牌。

## 二、账号类型核对

1. 确认当前登录的是不是**车主账号**。家人/分享账号通常能看到车辆、能做部分车控，但没有数字钥匙权限，官方 App 里也不会出现可用的蓝牙钥匙。
2. 用主账号在官方 App 打开该车的蓝牙钥匙/数字钥匙页面，确认状态是「已激活」且未过期。如果官方 App 自己也提示未激活，本 App 一定报错，先去官方恢复。
3. 在官方 App 里重新登录过一次后，回本 App 用主账号登录一次，再检查蓝牙钥匙。

## 三、回归

1. 车况刷新、锁车/解锁、车窗、后备箱、鸣笛、空调、座椅加热通风、寻车。
2. 蓝牙钥匙页：手动锁车/解锁、持续连接恢复、RSSI 与无感状态。
3. 原厂无感：设置页参数来源标记、12 秒测距验证、后台进区域事件。
4. 小组件：锁车/解锁快捷动作、刷新与样式切换。
5. 充电页：开始/停止、预约、充电口电子锁（都需要安全码）。

## 四、记录

失败项按「页面 → 按钮 → 当时状态（登录账号类型、是否车主、是否在充电/执行中）→ 诊断里的业务码与「交换凭据」行 → 截图」记录。这一版的自愈日志足以区分「令牌失效」与「权限不足」，请把那一行一起截图。
